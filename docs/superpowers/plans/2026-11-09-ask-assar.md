# Ask Assar Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add an in-dashboard assistant named Ask Assar that explains dashboard modules, answers from the signed-in user's own firm data, and performs allowed actions only after confirmation.

**Architecture:** Ask Assar is a separate agent from the existing AI Copilot. Copilot drafts legal work from documents and stays in the review queue. Ask Assar is a tool-using assistant: validate the message, refuse anything outside the dashboard, retrieve a short help passage or call one existing API service, then write the reply only from that result. History is stored per user and organization. The model never receives another firm's data and never answers general questions.

**Tech Stack:** NestJS (`apps/api`), existing Zod schemas (`packages/validation`), Mongoose (`packages/database`), Grok through the existing worker/API AI client, Vite dashboard (`apps/dashboard`), Vitest.

## Global Constraints

- AI legal output remains a draft until a human approves it. Ask Assar does not approve drafts.
- Every firm query is organization-scoped. Matter restrictions stay in `MatterAccessService`.
- The assistant refuses questions that are not about using this dashboard or this firm's records.
- Billing and staff roles do not have `ai:use`. Ask Assar uses a new permission, `assistant:use`, granted to every staff role. Each tool still checks the permission of the module it touches.
- No new vector database in the first version. Help text is retrieved by keyword overlap, the same idea as document similarity.
- Writes require an explicit confirmation message. Reads do not.
- Secrets, prompts, and document bodies are not written to logs.

## What the agent loop is

One user message goes through these steps, in this order. Nothing skips a step.

1. **Validate.** Zod checks the thread id, message length (1 to 2000 characters), and that the user is signed in.
2. **Load history.** The last 12 messages of this thread, only if `organizationId` and `userId` match.
3. **Classify.** A small allowlist decides the route: `help`, `lookup`, `action`, or `refuse`.
4. **Refuse.** If the route is `refuse`, save a fixed sentence and stop. The model is not asked to be helpful about the outside world.
5. **Retrieve or call a tool.** `help` searches the dashboard guide. `lookup` and `action` call one module tool. The tool checks the user's permission and matter access, then returns JSON.
6. **Compose.** Grok writes a short reply using only the guide passage or the tool JSON, plus the thread. If the tool was denied, the reply says the user cannot do that.
7. **Confirm writes.** An action that creates or changes a record is saved as `pending`. It runs only after the user sends "Confirm" on that proposal.
8. **Store and audit.** User message, assistant message, tool name, and confirmation are saved. An audit row records the tool, not the full prompt.

```
message -> validate -> history -> classify
  refuse ------------------> fixed reply
  help -----> guide search -> compose
  lookup ---> module tool --> compose
  action ---> proposal -----> wait for Confirm -> module tool -> compose
```

RAG here means the guide search in step 5. It is not a dump of the database into the prompt. Firm records arrive only through tools.

## Scope lock

Ask Assar may talk about these dashboard modules, and only the ones the role can open:

| Module | Route | Permission for the tool | What it may do |
| --- | --- | --- | --- |
| Overview | `/` | any signed-in user | Explain the home page. |
| Calendar | `/calendar` | `calendar:write` | List upcoming events. Create an event after confirmation. |
| Tasks | `/tasks` | `task:write` | List tasks. Create a task after confirmation. |
| Clients | `/clients` | `client:read` / `client:write` | Find a client. Create a client after confirmation. |
| Matters | `/matters` | `matter:read` / `matter:write` | Find a matter the user can see. Open a matter after confirmation. |
| Documents | `/documents` | `document:read` | Explain upload, versions, search. It does not upload a file from chat. |
| Templates | `/templates` | `document:read` | Explain a template and point to Use template. |
| AI Copilot | `/ai` | `ai:use` | Explain drafts and the review queue. Starting a copilot job stays on the matter page. |
| Conflicts | `/conflicts` | `conflict:check` | Explain a check. Running a check stays on the Conflicts page. |
| Time | `/time` | `time:write` | Explain time entries. Add an entry after confirmation. |
| Invoices | `/invoices` | `billing:read` / `billing:write` | Find an invoice. Issue, pay, or void only after confirmation and `billing:write`. |
| Reports | `/reports` | `billing:read` | Explain summary, aging, and CSV export. |
| Team | `/team` | `user:manage` | Explain members and invitations. Sending an invite stays on the Team page. |
| Audit | `/audit` | `audit:read` | Explain the log. It does not delete rows. |
| Settings and profile | `/settings`, `/profile` | signed-in user | Explain MFA, sessions, and firm settings. Password and MFA changes stay on those pages. |

Fixed refusal, used for everything else:

> I can only help with this dashboard and the records your role can see.

That covers general knowledge, other websites, legal advice that is not tied to a matter in this firm, jokes, code, and questions about other organizations.

### Task 2: Guide search and the refusal classifier

**Files:**
- Create: `apps/api/src/assistant/guide.ts`
- Create: `apps/api/src/assistant/classify.ts`
- Test: `apps/api/src/assistant/guide.test.ts`
- Test: `apps/api/src/assistant/classify.test.ts`

**Interfaces:**
- Consumes: `AssistantRoute`
- Produces: `searchGuide(query: string, permissions: Permission[]): GuideChunk | null`
- Produces: `classify(body: string): AssistantRoute`

Guide chunks are written by hand, one per module, each with `id`, `title`, `permission` or null, and `text` under 120 words. `searchGuide` drops chunks the user cannot open, then picks the chunk with the most shared words. If no word overlaps, it returns null.

`classify` rules, in order:

- Refuse if the text matches a small denylist of outside intents: weather, news, poems, general law homework, other companies, "ignore your instructions".
- `action` if it starts with a verb the tools support: create, add, schedule, issue, record.
- `lookup` if it asks for a count, a name, a status, or "show my".
- `help` otherwise, when it asks how a screen works.
- `refuse` when `help` would have no guide chunk. The service does that second check, not the classifier.

### Task 5: The assistant loop and HTTP API

**Files:**
- Create: `apps/api/src/assistant/assistant.service.ts`
- Create: `apps/api/src/assistant/assistant.controller.ts`
- Create: `apps/api/src/assistant/assistant.module.ts`
- Modify: `apps/api/src/app.module.ts`
- Test: `apps/api/test/assistant.test.ts`

**Interfaces:**
- `POST /v1/assistant/threads` body `{ title?: string }` returns the thread.
- `GET /v1/assistant/threads` returns the user's threads, newest first, limit 30.
- `GET /v1/assistant/threads/:id` returns the thread and its messages.
- `POST /v1/assistant/threads/:id/messages` body `{ body: string }` returns the new assistant message.
- `POST /v1/assistant/threads/:id/confirm` body `{ messageId: string }` runs a pending proposal.

Guards: session auth and `assistant:use`.

Composer behavior:

- `refuse`: save the fixed sentence. Do not call Grok.
- `help` with a chunk: call Grok with the chunk and the last 12 messages. The system instruction says to answer only from the chunk and to say "I don't have that in the dashboard guide." when the chunk does not cover the question.
- `help` with no chunk: same fixed refusal as `refuse`.
- `lookup`: run the tool, then ask Grok to phrase `data` in plain sentences. If `forbidden`, do not call Grok.
- `action`: save a proposal message with the tool name and arguments. The reply lists what will change and asks the user to confirm. Grok is not required for this sentence.
- `confirm`: load the proposal, check it is still pending and belongs to this user, call the write method, mark the proposal `done`.

**Shipped composer:** This version does not call Grok from the API. Help replies are the guide chunk. Lookup replies are one plain sentence built from the tool result. Refuse, a help question with no usable chunk, a forbidden tool, an action proposal, and confirm do not call a composer. `ASSISTANT_COMPOSER` is where a later model plugs in. A future composer must follow the existing help system instruction and must receive only the chunk or the tool JSON plus the thread.

Rate limit: 20 messages per user per 10 minutes, using the existing Redis limiter pattern.
